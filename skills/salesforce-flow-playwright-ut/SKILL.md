# Salesforceフロー単体テスト自動化

設計書・単体テスト仕様書を期待値の正本、対象組織から取得済みのFlowメタデータを実装状態の正本として、非画面フローの起動条件、分岐、データ操作、エラー経路を追跡可能なテストとして実装・実行する。

## 境界を確定する

1. 対象フローの正式名、API参照名、種別、対象オブジェクト、設計書、テスト仕様書、メタデータ、接続先組織、実行ユーザーを特定する。
2. レコードトリガーフローまたは自動起動フローなどの非画面フローであることを確認する。画面フローは別の自動化として分離し、本スキルで推測実装しない。
3. オブジェクト設計書のテストは対象外とする。フロー固有の手順・コード・設定は独立させ、明示依頼なしに別用途の自動化へ統合しない。
4. 原本の設計書、テスト仕様書、メタデータZIP・XMLは参照専用とする。結果はコピーまたは新規出力へ記録する。

資料不足だけを理由に作業を止めず、取得済み資料から事実、解釈、未確定事項を分ける。期待結果や更新対象を確定できない場合は推測で実行せず、未確定のまま実装可能な参照・解析・テスト基盤まで進める。

## 定義とケースを対応付ける

設計書から、開始条件、実行タイミング、条件ロジック、Decision、Get Records、Create／Update／Delete Records、Assignment、Loop、Subflow、Action、Fault経路を抽出する。メタデータと照合し、設計値を現在の実装値で置き換えない。

ケースの網羅と独立性は [references/flow-coverage.md](references/flow-coverage.md) に従う。既存の単体テスト仕様書がある場合はケースNo.と枝番を維持し、自動実行できないケースも削除せず理由付きで残す。活動管理を扱う場合は、テストデータ作成前に [references/activity-management-domain.md](references/activity-management-domain.md) を読み、レコードタイプ別の件数制約を守る。

## 自動化を追加・調整する

1. ワークスペースの既存コマンド、設定、テスト、証跡生成処理を読み、フロー用の入口と不足機能を特定する。
2. フロー固有処理を独立したモジュールとテストとして追加する。オブジェクト用の固定組織ID、レコードID、セレクター、保存許可、成功履歴を流用しない。
3. メタデータ解析とローカル試験を先に実装し、Flow XMLから対象定義と分岐を再現可能に抽出できることを確認する。
4. 業務データの操作が必要なケースは、対象ケース、操作ユーザー、作成・更新対象、通知・外部連携への影響、後片付け方針が承認範囲にあることを確認してから実機処理を有効にする。
5. テストデータ準備と実行結果確認は許可済みの専用レコードに限定する。Flow定義、バージョン、有効状態、権限、User、組織設定は参照だけにする。
6. 新規テストレコードの表示名は、画面上で用途を判別できるよう `UT_<対象ID>_No<ケースNo>_<役割>_<実行日>` を基本形にする。役割には「対象顧客」「対象活動」「完了活動」「対象外顧客」など業務上の意味が分かる日本語を使い、ランダム文字列や `ACCOUNT`、`OPEN1` だけの名称にしない。証跡では「対象外顧客（今回の対象顧客とは別）」のように役割を補足する。時刻は表示名へ入れず、再実行分はレコードIDと実行IDで区別する。既存レコードは改名しない。

実装・実行の安全境界と結果状態は [references/safety-and-evidence.md](references/safety-and-evidence.md) に従う。Flowの配備、有効化、無効化、保存、バージョン切替を自動化へ追加しない。

## 検証する

- 解析テストでは、実メタデータまたは機密情報を除いた固定fixtureを使い、開始条件、条件ロジック、全Decision結果、既定結果、Fault接続、更新項目を検証する。
- 実行テストでは、ケースごとに事前状態、起動操作、実行ユーザー、期待経路、期待更新、対象外レコードの変更なし、実結果を記録する。
- 同一ケースの再実行は新しい試行として残す。保存・更新の成否が不明な場合は読み取りで現状を照合し、同じ操作を無条件に再送しない。
- 証跡の再生成では保存済み記録を使い、Salesforce操作を繰り返さない。

## 完了条件

対象ケースについて、設計書との対応、使用したFlowメタデータの出所とハッシュ、実行前提、通過経路、データの前後状態、判定、ケース別証跡を追跡できる状態にする。未実装、未実行、設定取得不能、権限不足、通信障害、自動化エラーは製品のOK／NGと分離する。ローカル解析の成功をSalesforce実機テストの成功として報告しない。
